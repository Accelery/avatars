Avatar API documentation

One endpoint, deterministic PNG avatars, no account.

Quick start

Put an avatar URL in any <img> tag. The string after the slash is the seed.

<img
  src="https://api.genavatar.me/user@example.com?size=128"
  alt=""
  width="128"
  height="128">

The same ID always returns the same face. Omit the path for a random avatar.

URL format

Request Result
GET /{id} Deterministic avatar for the ID
GET / New random avatar on each request

IDs can be usernames, emails, UUIDs, Unicode, or emoji. The API uses the first 36 characters.

Size

Add ?size= to request a square PNG from 16 to 400 pixels. The default is 400. Invalid values fall back to 400.

https://api.genavatar.me/alice?size=64
https://api.genavatar.me/alice?size=128
https://api.genavatar.me/?size=192

Use a size close to the rendered size. A 64px avatar doesn't need a 400px image.

Analytics opt out

Add ?notrack=true to skip usage analytics. The avatar is still returned.

https://api.genavatar.me/alice?notrack=true

Caching

Named avatars use Cache-Control: public, max-age=31536000, immutable. Random avatars use no-store in the browser.

The Worker also caches rendered faces per size, so it doesn't draw the same face twice at the same edge location.

CORS

Responses include Access-Control-Allow-Origin: * and expose the avatar headers. Canvas and fetch code can use the images.

const res = await fetch("https://api.genavatar.me/alice?size=64");
const size = res.headers.get("X-Genavatar-Size");
const blob = await res.blob();

Response headers

Header Value
Content-Type image/png
X-Genavatar-Id The ID used for the request, or a UUID for random requests
X-Genavatar-Size The returned square size in pixels
X-Cache-Status HIT or MISS

Errors

Status Meaning
404 Blocked path
405 Method other than GET or HEAD
